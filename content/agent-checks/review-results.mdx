Run a check against a branch, a commit, or a revision range, then use its findings to decide what to change.

## Run a check manually

Organization owners can start checks for any connected repository. The agent does not need to watch the repository or have automatic events enabled.

1. Open [Agent checks](/orgs/_/agents/checks).
2. Click **Run a review**.
3. Select a repository.
4. Select the agents under **Reviewers**.
5. Expand **Choose a revision or range** to enter revisions, or keep the defaults for the default branch's latest commit.
6. Click **Run review**.

Each selected agent starts a separate check.

### Choose a revision or range

| Field          | Use                                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Ref**        | A branch or tag. Leave empty to use the default branch.                                                               |
| **Commit SHA** | A full 40-character commit SHA that overrides the selected ref's head.                                                |
| **Base**       | A branch, tag, or full commit SHA for the start of the comparison. Leave empty to use the head commit's first parent. |
| **Head**       | A branch, tag, or full commit SHA for the end of the comparison. Use this instead of **Ref** and **Commit SHA**.      |

For example, set **Base** to `main` and **Head** to `feature/api-change` to review the difference between their current tips. Depot resolves the revisions when you start the check. Do not combine **Head** with **Ref** or **Commit SHA**.

Without an explicit base, a manual check reviews one commit against its first parent, not the entire branch's changes. A first commit is compared against an empty tree.

## Find a check

Open **Checks** to see recent checks. Use the filters to narrow the list by status, repository, branch, agent, or commit SHA. Select a check to inspect its revisions, model, timing, summary, and findings.

## Interpret the outcome

| Outcome                  | Meaning                                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| **Queued**               | The check is waiting to start.                                                                            |
| **Running**              | The agent is reviewing the change.                                                                        |
| **Passed**               | The agent passed the change without findings.                                                             |
| **Passed with findings** | The agent passed the change and reported advisory findings.                                               |
| **Needs changes**        | The agent decided the change should not merge as-is. The decision can include findings or only a summary. |
| **Resolved**             | Someone resolved every finding on a check that needed changes.                                            |
| **Couldn't finish**      | The check failed to complete. Read the error before starting another check.                               |

A completed review and a successful execution are different from a passing decision. Read the summary even when there are no findings.

## Act on findings

Each finding includes its severity, explanation, and file location. Use **Copy finding** to copy one finding, or **Copy as prompt** from the check actions to take the result into your coding agent.

For checks with the **Needs changes** outcome, organization members can click **Resolve** on an individual finding or resolve all remaining findings. Resolving every finding changes the displayed outcome to **Resolved**. Use **Unresolve** to reopen a finding.

Resolving a finding records your decision without changing code or running another review. If a check has the **Needs changes** outcome but no findings, you cannot resolve it through finding controls.

Run another check to review updated code. If a newer attempt replaces an earlier attempt, the earlier findings become read-only.

## Inspect the transcript

Read the **Transcript** section in the check details to inspect the recorded session behind the decision and findings. It shows the agent's messages, reasoning, and tool calls with their arguments and outputs.

Transcripts are available after completion; failed checks and some older checks do not have one. Transcripts expire after 30 days. The dashboard shows whether a transcript expired or was never recorded.

## See results in GitHub

GitHub review results are published as commit checks named `Depot Review: <agent-name>`. Publication requires a GitHub Checks connection with access to the repository.

To connect a GitHub Checks app, follow these steps. You must be an organization owner, and GitHub Code Access must already be connected.

1. Open [Connections in Organization Settings](/orgs/_/settings/connections#github-checks).
2. Under **GitHub Checks**, connect the offered **Depot Checks** app for your GitHub account.
3. Grant the app access to the repository.

A passing decision publishes a successful GitHub check, including when the review has advisory findings. A failing decision publishes a failed check. Resolving every finding changes that check to success; reopening a finding changes it back to failure. A failing decision with no findings stays failed.

An execution failure publishes a neutral check so that a review that couldn't finish does not block merging. Follow the check's link to Depot to read the full result.

## Troubleshoot a check

### The repository is missing

Confirm that the repository connection grants Depot access. All connected repositories appear in the manual run form, whether or not an agent watches them. Empty repositories need a commit before they can be reviewed.

### The selected revision is unavailable

Check that both ends of the range exist in the connected repository. Use full 40-character commit SHAs. You can use **Ref**, **Commit SHA**, or both together. Use **Head** instead of those fields.

### Depot cannot confirm that a review started

Check the list before starting another review. The request may have started a check even if the response did not arrive.
